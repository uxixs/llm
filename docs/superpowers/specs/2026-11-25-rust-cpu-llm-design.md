# Rust CPU LLM — 설계 문서

작성일: 2026-11-25

## 1. 의도와 이유

노트북 CPU만으로, Rust로 GPT형 언어모델을 **처음부터 직접 구현**하고 학습시킨다.

- 핵심 가치는 두 가지: (1) 모든 연산(forward/backward, 옵티마이저, 토크나이저, 커널)을 직접 짜면서 원리를 이해하는 것, (2) 이 노트북에서 **연산을 최대한 빠르게** 만드는 것. 속도를 위해 SIMD intrinsics, 인라인 어셈블리까지 허용.
- 결과물: 레딧 Q&A 데이터로 학습된 **대화형 소형 모델** + 그것을 돌리는 직접 짠 엔진.
- **학습 예산: 실행 1회당 벽시계 60초** (사용자 결정 — 결과를 빠르게 받아보고 싶음). 모든 학습 실행(사전학습 + SFT 합산)은 60초 안에 끝난다. 데이터 다운로드·전처리·토큰화는 미리 한 번 해두고 60초에서 제외. 프로세스 시작~모델 로드도 제외, 첫 학습 스텝부터 계측.
- 이 예산이 프로젝트를 **"60초 스피드런"** 으로 만든다: 핵심 지표는 *60초 학습 후 검증 손실*. 커널이 빨라질수록 같은 60초에 더 많은 토큰을 학습 → 손실이 내려감. 속도 최적화와 모델 품질이 하나의 숫자로 묶임.
- 성공 기준: 60초 학습한 모델이 `<|user|>…<|assistant|>…<|end|>` 형식을 지키고, 질문 주제와 관련된 단어가 섞인 레딧풍 영어 문장(문법은 국소적으로만 맞음)을 생성. 처음 합의한 "그럴듯한 ELI5 답"은 60초 규모에서는 기대치보다 낮아질 수 있음 (6절 참고). 그리고 그걸 빠르게 돌리는 직접 짠 엔진.

## 2. 목표 / 비목표 / 반목표

**목표**
- 손으로 쓴 GPT 학습·추론 파이프라인 (자동미분 라이브러리 없음).
- 단계별로 측정 가능한 속도 향상: 스칼라 기준 → 캐시 블로킹 → AVX-512 → 멀티스레드 → asm 커널.
- Muon 옵티마이저 + 소규모 학습 트릭으로 학습 효율 향상.
- BitNet b1.58 삼진 가중치 변형을 학습하고, VNNI 기반 정수 추론 커널로 fp32 모델과 비교.
- 터미널 채팅 CLI.

**비목표**
- GPU 지원, 범용 텐서/autograd 라이브러리, 웹 UI, 사실 정확도, 모델 배포.

**반목표** (동작해도 실패로 보는 것)
- 연산 경로에 외부 ML/BLAS 크레이트 사용 (ndarray, candle, burn, matrixmultiply, BLAS 바인딩 등) — 직접 구현 목적을 무너뜨림.
- 정확성 검증 없이 들어간 최적화. 모든 빠른 커널은 스칼라 기준 구현과 수치 비교 테스트를 통과해야 함.
- 레딧 데이터로 학습한 모델/가공 데이터의 공개 배포 (레딧 약관상 학습 이용 제한, 개인 학습용 한정).

## 3. 제약

- 하드웨어: Intel i7-1165G7 (Tiger Lake, 4코어/8스레드), RAM 16GB, GPU 없음(Iris Xe 미사용).
  - 지원 ISA: AVX2, FMA, **AVX-512 F/BW/VL/DQ/VNNI**. 클라이언트 Tiger Lake는 512비트 FMA 유닛 1개 → 코어당 사이클당 fp32 32 FLOP. 전체 코어 이론 피크 대략 300–400 GFLOPS (발열로 클럭 변동).
- OS: Windows 11. Rust 1.99.1 설치됨. 빌드는 `-C target-cpu=native`.
- **실행 대상은 이 노트북 하나** (사용자 요구 "노트북에서 돌아가야 함"). 다른 머신 이식성 불필요. 따라서 스칼라 경로는 정확성 기준용이고, 성능을 튜닝한 AVX2 대체 커널은 만들지 않는다 — *설계자 판단*.
- 학습 시간 예산: 실행 1회당 60초 (1절).
  - 계산: 최종 최적화 단계에서 실효 50–100 GFLOPS 가정 → 60초에 약 3–6×10¹² FLOP. 학습 비용 ≈ 6 × 파라미터 × 토큰이므로 **약 100만 파라미터 모델로 50만~100만 토큰** 학습이 상한.
  - 스칼라 기준 단계(수 GFLOPS)에서는 60초에 수만 토큰만 학습 → 출력은 거의 무의미. 이 차이 자체가 최적화 효과를 보여주는 결과.
- 메모리: 모델이 작아 수백 MB 이내.

## 4. 접근 방식 검토

| 방식 | 내용 | 장단점 | 결정 |
|---|---|---|---|
| A. 레이어별 수동 forward/backward | 고정 GPT 구조, 각 연산 미분을 직접 유도해 코드로 작성 (llm.c 스타일) | 가장 빠름, 수학 이해 최대. 구조 변경 시 backward 재작성 필요 | **채택** |
| B. 범용 autograd 텐서 라이브러리 | 미니 PyTorch를 만든 뒤 GPT 구성 | 유연하지만 할당·그래프 오버헤드로 느리고 코드량 2배. "빠른 모델" 목표와 어긋남 | 기각 |
| C. 커널 전체를 인라인 asm | | intrinsics 대비 이득 수 % 수준, 난이도 급상승 | A 위에 **마지막 실험 단계**로 축소 채택 (matmul 마이크로커널 1개) |

실험적 기법 검토 결과 (사용자가 추천 조합 선택):
- **채택**: Muon, 소규모 학습 트릭(ReLU², weight tying, logit softcap, 다중 토큰 예측), BitNet b1.58 + VNNI 커널.
- **기각**: RWKV(수식 복잡, 소규모에서 이득 불확실), SLIDE(대규모 출력 문제 전용, 소형 LM에선 손해 가능성), Forward-Forward/zeroth-order(LM 사전학습 성능 열악).

## 5. 결정된 설계

### 5.1 데이터
- 출처: **Pushshift 레딧 서브레딧 덤프** (zstd 압축 NDJSON, academic torrents 배포). API 크롤링 안 함. 덤프 다운로드는 사용자가 직접 수행.
- 서브레딧: r/explainlikeimfive, r/NoStupidQuestions, r/AskScience (Q&A형, 어시스턴트 말투에 가까움).
- **사전학습 코퍼스**: 위 서브레딧의 게시글 본문 + 댓글. 60초에 보는 토큰은 ~100만 개뿐이므로 **약 20–50MB 텍스트**면 충분 (실행마다 겹치지 않는 구간을 쓰거나 같은 구간을 고정해 비교 — 비교 실험은 고정 구간).
- **대화 미세조정(SFT) 데이터**: (질문 = 게시글 제목 + 본문) → (답 = 점수 높은 최상위 댓글) 쌍.
  - 필터: 점수 임계값, 길이 제한(컨텍스트에 들어갈 것), `[deleted]`/`[removed]` 제거, URL·마크다운 정리, 봇 댓글 제거.
  - 형식: `<|user|>{질문}<|assistant|>{답}<|end|>`. 손실은 **assistant 토큰에만** 적용.
  - **SFT는 r/explainlikeimfive 위주** (성공 기준이 ELI5 말투). 나머지 두 서브레딧은 사전학습 코퍼스에만 쓰고, SFT에는 짧고 쉬운 답만 소량 섞는다 — *설계자 판단*.
  - SFT는 **단일 턴**. CLI의 여러 턴 유지는 최선 노력(best-effort)이며 품질 보장 대상 아님 (이 규모에서 다중 턴 맥락 유지는 어렵다고 사용자와 합의). 다중 턴 SFT 데이터(OP 후속 댓글 체인)는 선택적 후속 작업 — *설계자 판단*.
- 학습/검증 분할: 게시글 단위로 분할(같은 게시글이 양쪽에 들어가지 않게).

### 5.2 토크나이저
- **바이트 단위 BPE 직접 구현** (학습 + 인코딩 + 디코딩). 어휘 크기 **2048 기본** (약 100만 파라미터 모델에서 큰 어휘는 embedding이 파라미터를 독식). 1024/4096은 비교 실험.
- 특수 토큰: `<|user|>`, `<|assistant|>`, `<|end|>`, `<|pad|>`(필요 시).
- 사전학습 코퍼스로 BPE 학습, 토큰화 결과는 바이너리(u16) 파일로 저장해 학습 시 mmap/스트리밍.

### 5.3 모델 (기준 구성)
- 디코더 전용 GPT, pre-norm.
- RMSNorm, RoPE 위치 인코딩, causal multi-head attention, MLP 활성화 **ReLU²**, bias 없음.
- 입력 embedding과 출력 projection **가중치 공유**.
- 출력 logit **softcap** (`c * tanh(z / c)`).
- **다중 토큰 예측**: 다음 1개 + 추가 토큰(예: +2) 예측 헤드를 끄고 켤 수 있는 옵션. 기본 꺼짐, 실험으로 비교.
- 기준 하이퍼파라미터: d_model 128, 레이어 4, 헤드 4, 컨텍스트 256, 어휘 2048 → 약 100만 파라미터 (embedding ~26만 + 블록 ~79만). 60초 손실 기준으로 크기 조정 — 엔진이 빨라지면 최적 모델 크기도 커짐.

### 5.4 학습
- fp32 마스터 가중치, 레이어별 수동 forward/backward. 학습 중 활성값은 backward용으로 저장.
- **옵티마이저**: 은닉층 2D 행렬은 **Muon**(모멘텀 + Newton–Schulz 직교화), embedding·norm 게인은 AdamW (modded-nanogpt 방식).
- **LR 스케줄은 스텝 수가 아니라 경과 시간 기준** (warmup → 일정 → 마지막 구간 감쇠). 엔진 속도와 무관하게 60초에 맞춰 끝나야 하므로.
- 한 실행 = 사전학습 약 45초 → SFT 약 15초, 합계 60초에서 자동 종료 — *설계자 판단, 비율은 조정 가능*.
- 종료 시 가중치 저장 (채팅 CLI가 로드). 실행이 짧아 중간 체크포인트·재개는 불필요.
- 고정 시드: 같은 설정은 같은 데이터 순서로 실행 (비교 공정성). 단, 벽시계 예산이라 학습 토큰 수는 실행마다 약간 달라질 수 있음 — 기록.
- 로그: 스텝별 학습 손실, 종료 시 검증 손실, 학습한 토큰 수, tokens/sec, 실효 GFLOPS.

### 5.5 정확성 검증
- 모든 연산에 **스칼라 기준 구현**을 둔다.
- 각 연산 backward는 **유한 차분 기울기 검사** 테스트로 검증 (작은 크기, f64 비교도 허용).
- 최적화 커널(블로킹/AVX-512/스레드/asm/VNNI)은 기준 구현과 허용 오차 내 일치 테스트.
- 작은 데이터 과적합 테스트: 수백 토큰을 외워 손실이 ~0으로 가는지.

### 5.6 성능 단계 (각 단계 측정 후 다음 단계)
1. 스칼라 기준 (정답 기준점).
2. 캐시 블로킹 / 메모리 레이아웃 최적화.
3. AVX-512 intrinsics (`std::arch`), 런타임 기능 감지 + 스칼라/AVX2 대체 경로.
4. 멀티스레드: 표준 라이브러리 스레드 기반 직접 구현 스레드 풀 (rayon 미사용).
5. 실험: matmul 마이크로커널을 `asm!` 인라인 어셈블리로 재작성, intrinsics 버전과 벤치마크 비교.
- 벤치마크 하네스: 커널별 GFLOPS(측정 피크 대비 %), 학습 tokens/sec, 추론 tokens/sec. 단계별 결과를 표로 기록.

### 5.7 BitNet b1.58 변형
- 선형층을 BitLinear로 교체: 가중치는 absmean 기준 {-1,0,+1} 양자화, 활성값은 토큰별 absmax int8 양자화, 학습은 fp32 잠재 가중치 + STE.
- 기준 fp32 모델과 **같은 데이터·구성·60초 예산**으로 처음부터 학습해 비교 (BitNet은 양자화 비용으로 60초에 보는 토큰이 적을 수 있음 — 그 자체가 비교 결과).
- 추론 커널: 2비트 팩킹 가중치 + int8 활성값, AVX-512 VNNI(`vpdpbusd`) 정수 내적.
- 비교 지표: 검증 손실, 추론 tokens/sec, 모델 파일 크기, 고정 프롬프트 출력.

### 5.8 채팅 CLI
- 터미널 대화 루프, 컨텍스트 창 안에서 여러 턴 유지(넘치면 오래된 턴부터 잘라냄).
- KV 캐시, temperature / top-p 샘플링, `<|end|>`에서 정지.
- fp32 모델 / BitNet 모델 선택 실행, 생성 속도(tokens/sec) 표시.

### 5.9 평가
- **주 지표: 60초 학습 후 검증 손실** (사전학습 검증셋, SFT 검증셋 각각). 모든 단계·기법 비교는 이 숫자로.
- 결과표 한 줄 = 한 실행: 엔진 단계, 기법 조합, 학습 토큰 수, tokens/sec, 검증 손실.
- 고정 질문 세트 20–30개에 대한 출력 비교 (구성/기법별).
- 성능 표(5.6), fp32 vs BitNet 표(5.7).

### 5.10 의존성 정책
- 연산 경로(토크나이저, 모델, 학습, 추론, 커널): **외부 크레이트 없음**.
- 데이터 준비 도구(zstd 해제, JSON 파싱): 외부 크레이트 허용 — *설계자 판단*. 학습 대상이 아니라 입력 정리용이라서.

## 6. 기대치

60초·약 100만 파라미터 규모에서 예상되는 출력: 대화 형식 토큰과 레딧풍 어휘는 학습되지만, 문장은 몇 단어 단위로만 자연스럽고 질문과의 연관성은 약함. "그럴듯한 ELI5 답"은 어렵다. 나중에 원하면 같은 엔진으로 예산만 늘려(예: 10분, 1시간) 품질을 올릴 수 있음 — 예산은 설정값 하나로 둔다.

## 7. 빌더에게 맡기는 것
- 크레이트/모듈 구성, 파일 포맷 세부(체크포인트, 토큰 파일).
- 스레드 풀 구조, 블록 크기, 메모리 레이아웃, 커널 세부.
- 하이퍼파라미터 세부 조정(LR, 배치, Muon 계수, softcap 값, 학습 토큰 수).
- 데이터 필터 임계값 세부.
- 단계별 구현 순서는 5.5–5.6을 따르되, 그 안의 세분화는 자유.
